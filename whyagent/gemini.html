Gemini turns a proven mistake into a rule

Finding the edit that broke the test is half the job. The other half is making sure no agent makes that mistake again. Once the cause is proven, Gemini reads the agent's reasoning, the error it was reacting to and the bad edit, and writes a one-sentence lesson. agentwhy then tests that lesson on fresh agents before it's allowed into anyone's rulebook.

Where Gemini is used in the pipeline

Every model call in agentwhy goes to Gemini first. The steps before this are all real test runs, so no model ever decides the cause.
  1. Write a lessonCheck saved lessons firstIf a proven lesson for this file and error is already in Tiger Data, it's reused and Gemini isn't called.
  2. Write a lessonWrite the ruleGemini (gemini-flash-latest) gets the agent's reasoning, the error it saw and the diff of the proven edit, and writes one rule. Rules may never tell an agent to edit the tests.
  3. Test the lessonRerun the taskFresh agents get the same task from just before the bad edit, half with the rule and half without. The Gemini CLI is one of the two agents that can do these reruns.
  4. AnswerKeep it only if it worksThe rule is saved only if agents with it do measurably better (Fisher's exact test). Then every new agent session starts with it.
