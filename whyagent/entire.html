Entire is where the evidence comes from

git blame can tell you who changed a line. Only the agent's recorded session can tell you why. Entire records every coding-agent session and links it to the commit it produced, and that recording is agentwhy's input: without it there are no edits to search, no reasoning to show, and nothing to learn from.

Where Entire is used in the pipeline

Five of the twelve steps in the pipeline view depend on what Entire recorded, and the answer goes back to it.
  1. Find the commitRead the checkpoint trailerEvery commit made in a recorded session carries an Entire-Checkpoint trailer. No trailer means a person wrote it, and agentwhy stops there.
  2. Entire: open the sessionLoad the transcriptThe session behind that checkpoint: the task the agent was given, every edit, every command, what it was thinking and what it saw on screen.
  3. Rebuild the agent's workTurn it into replayable editsOne commit becomes an ordered list of edits, including ones made with shell commands, and replaying them must rebuild the commit exactly.
  4. Search the editsBisect inside the commitgit bisect stops at a commit. With Entire's edits we keep going, down to the single edit that broke the test.
  5. Prove itShow the reasoningThe proven edit comes with the agent's own words and the error it was reacting to, straight from the transcript.
  6. AnswerPost back to the trailWith --trail, the root cause, proof and lesson are posted as a finding on the branch's Entire trail, with the revert as a suggested patch.

Without Entire

An agent's commit stays a black box.

git bisect would point at "the agent's commit" and stop. A commit with nine edits across four files would still need a person to read all of it, git blame would point at whichever edit last touched the failing line (often the wrong one), and there would be no reasoning to turn into a lesson for the next agent.
